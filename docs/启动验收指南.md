# 贝壳 v1.0 底座+线索CRUD 联合验收指南

## 0. 启动前准备（必须先做）

### 0.1 初始化数据库
```bash
cd docs/sql
mysql -u root -p < init.sql
```
验证：`mysql -u root -p beike_platform -e "SHOW TABLES;"` 应有 8 张表。

### 0.2 生成测试密码哈希（关键！）
SQL 中的哈希只是占位符，必须用本机 BCrypt 重新生成：
```bash
cd backend-monolith
# 方式1：直接用 Maven 执行（如果已配置）
mvn exec:java -Dexec.mainClass="com.beike.platform.PlatformApplication" 2>&1 | head -1
# 方式2：最简单——启动后用注册接口创建账号
```
或者写个临时 Java 类生成：
```java
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
public class Gen {
    public static void main(String[] a) {
        System.out.println(new BCryptPasswordEncoder().encode("123456"));
    }
}
```

### 0.3 修改 application.yml 数据库密码
`backend-monolith/src/main/resources/application.yml` 中 `spring.datasource.password` 改为你本机 MySQL root 密码。

### 0.4 启动后端
```bash
cd backend-monolith
mvn spring-boot:run
```
看到 `Started PlatformApplication` 即成功。

## 一、底座 7 项验收

### 1️⃣ 统一返回体
```bash
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | python -m json.tool
```
✅ 验证：`{"code": 200, "message": "操作成功", "data": {...}, "timestamp": ...}`
❌ 如果 password 不对 → 用 0.2 重新生成哈希 + 更新 init.sql + 重新导入

### 2️⃣ JWT 鉴权
```bash
# 先拿 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | grep -o '"token":"[^"]*"' | cut -d'"' -f4)

# 无Token → 401
curl -s http://localhost:8080/api/clue/page | grep "code"

# 有效Token → 200
curl -s http://localhost:8080/api/clue/page -H "Authorization: Bearer $TOKEN" | grep "code"

# 错误Token → 401
curl -s http://localhost:8080/api/clue/page -H "Authorization: Bearer wrong" | grep "code"
```

### 3️⃣ 密码加密
```sql
mysql> SELECT username, LEFT(password, 20) FROM sys_user WHERE username='admin';
```
✅ `password` 以 `$2a$` 开头（BCrypt 密文），无明文。

### 4️⃣ 逻辑删除
```bash
# 新增一条线索
curl -s -X POST http://localhost:8080/api/clue \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"clueName":"测试","clientCompany":"测","beikeOwner":"测","clueLevel":"B","clueStatus":"线索接触","deptBelong":"平台一部"}'

# 查 ID
curl -s "http://localhost:8080/api/clue/page?pageSize=1" -H "Authorization: Bearer $TOKEN" | grep -o '"id":[0-9]*' | head -1

# 删除
curl -s -X DELETE http://localhost:8080/api/clue/1 -H "Authorization: Bearer $TOKEN"

# 列表中不应再出现
curl -s "http://localhost:8080/api/clue/page" -H "Authorization: Bearer $TOKEN"
```
然后查数据库：`SELECT id, clue_name, is_deleted FROM biz_clue WHERE id=1;` → `is_deleted=1`

### 5️⃣ 全局异常
```bash
curl -s -X POST http://localhost:8080/api/clue \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"clueName":""}' | python -m json.tool
```
✅ `code=400`，message 提示校验失败的内容。

### 6️⃣ CORS
用浏览器 `http://localhost:5177` 直接调用登录接口，F12 Network 无红色 CORS 报错。

### 7️⃣ 审计字段
新增一条线索后：
```sql
SELECT id, clue_name, create_by, create_time, update_by, update_time FROM biz_clue ORDER BY id DESC LIMIT 1;
```
✅ `create_time`、`update_time` 自动填充，`create_by`、`update_by` 为登录用户 ID。

## 二、线索 CRUD 4 项验收

### 8️⃣ 权限控制
```bash
# 用普通员工登录
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"employee","password":"123456"}'
# 拿 EMP_TOKEN

# 尝试删除 → 应该返回 403
curl -s -X DELETE http://localhost:8080/api/clue/1 -H "Authorization: Bearer $EMP_TOKEN" | grep "code"
```
✅ 返回 `403`，库中数据未被删除。

### 9️⃣ 分页筛选
```bash
# 按状态筛选
curl -s "http://localhost:8080/api/clue/page?status=线索接触" -H "Authorization: Bearer $TOKEN"

# 日期范围
curl -s "http://localhost:8080/api/clue/page?dateFrom=2026-01-01&dateTo=2026-12-31" -H "Authorization: Bearer $TOKEN"
```

### 🔟 已转项目锁定
```sql
UPDATE biz_clue SET is_converted=1 WHERE id=2;
```
```bash
curl -s -X PUT http://localhost:8080/api/clue/2 \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"clueName":"编辑已转项目的线索","clientCompany":"XX","beikeOwner":"XX","clueLevel":"B","clueStatus":"线索接触","deptBelong":"平台一部"}'
```
✅ 返回错误提示「已转项目的线索不可编辑」。
