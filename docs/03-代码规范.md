### 1.2 Zustand 状态治理规则

**强制收敛**：
- ✅ **允许存**：`user`（用户信息）、`token`、`permissions`、`roles`、`isLoggedIn`
- ❌ **禁止存**：线索列表、项目列表、跟进记录等业务数据
- 业务数据由页面组件自己管理（`useState` + API 调用）

**整改拆分方案**：
原 `useDataStore` + `useLeadStore` 拆分为两个独立 Store：
- `useUserStore`：仅 `{ user, token, roles, permissions, isLoggedIn, login(), logout(), hasPermission() }`
- `useUiStore`：仅 `{ sidebarCollapsed, theme, globalLoading }`
- 所有业务 CRUD 方法（`addPipeline`、`updateLead` 等）全部移除，逻辑下移到 `api/` 层
- 统计数据的 `getStats` 改为调用 `GET /api/clue/stats`

**禁止行为**：
- ❌ 在 Store 中存放业务列表数据
- ❌ 在 Store 中定义业务 CRUD action

### 1.3 组件复用规则

| 组件 | 路径 | 复用要求 |
|------|------|---------|
| ProTable | `@/components/common/ProTable` | 所有列表页必须使用，传 columns + api |
| Permission | `@/components/common/Permission` | 所有按钮/菜单必须包裹 |
| FileUpload | `@/components/common/FileUpload` | 统一对接附件接口 |
| EmptyState | `@/components/common/EmptyState` | 所有空数据场景 |
| LoadingState | `@/components/common/LoadingState` | Skeleton 替代 |

**禁止行为**：
- ❌ 在业务组件中重新实现表格分页/筛选逻辑
- ❌ 在业务组件中手写权限判断逻辑
- ❌ 各模块独立写 Excel 导入组件（后续统一为一个）

### 1.4 命名规范

| 类型 | 风格 | 示例 |
|------|------|------|
| 组件文件 | PascalCase | `ClueDetail.tsx`, `FollowUpTimeline.tsx` |
| 变量/函数 | camelCase | `getClueList`, `handleSubmit` |
| 常量 | UPPER_SNAKE | `CLUE_STATUS_MAP`, `PAGE_SIZE` |
| 路由路径 | kebab-case | `/clue/detail/:id` |
| API 函数 | camelCase + 动词前缀 | `fetchClueList`, `createClue` |

### 1.5 交互规范

| 场景 | 要求 |
|------|------|
| 列表无数据 | `<EmptyState description="暂无线索" action="新建线索" />` |
| 详情无数据字段 | 显示 `—` 而非空白 |
| 提交中 | 按钮 loading + disabled，防重复点击 |
| 删除/批量操作 | 必须 `Popconfirm` 二次确认 |
| 接口报错 | `message.error(res.message \|\| '操作失败')` |
| 超长文本 | 默认收起 80 字，点击展开 |

## 二、后端代码规范

### 2.1 分层架构

```
com.beike.platform
├── controller/          # 接收请求 → 参数校验 → 调用 Service → 返回 Result
│   ├── AuthController
│   ├── ClueController
│   ├── ProjectController
│   ├── AttachmentController
│   └── SystemController
├── service/             # 业务逻辑层
│   ├── AuthService
│   ├── ClueService
│   ├── ProjectService
│   ├── AttachmentService
│   └── impl/            #   实现类
├── mapper/              # 数据访问层（MyBatis-Plus BaseMapper）
│   ├── ClueMapper
│   ├── ProjectMapper
│   └── ...
├── entity/              # 数据库实体（与表一一对应）
│   ├── BizClue
│   ├── BizProject
│   └── ...
├── dto/                 # 请求参数对象
│   ├── CluePageDTO
│   ├── ClueSaveDTO
│   └── ...
├── vo/                  # 返回数据对象
│   ├── ClueVO
│   ├── ClueDetailVO
│   └── ...
├── config/              # Spring 配置
├── common/              # 通用类
│   ├── Result.java      #   统一返回体
│   ├── BizException.java#   自定义异常
│   ├── GlobalExceptionHandler.java  # 全局异常处理
│   └── JwtUtil.java     #   JWT 工具
├── aspect/              # 切面
│   ├── AuditLogAspect   #   操作日志自动记录
│   └── PermissionAspect #   权限校验切面
└── PlatformApplication.java
```

### 2.2 强制规则

| 规则 | 说明 |
|------|------|
| **分层隔离** | Controller → Service → Mapper，禁止跨层调用 |
| **事务** | 所有写操作必须 `@Transactional(rollbackFor = Exception.class)` |
| **参数校验** | Controller 入参必须 `@Valid` + DTO 内 `@NotBlank` 等 |
| **异常处理** | 业务异常抛 `BizException`，由全局处理器统一返回 |
| **日志** | 操作日志通过 `@AuditLog` 注解自动记录，禁止手写 |
| **返回体** | 统一使用 `Result.success(data)` / `Result.error(code, msg)` |
| **SQL** | XML 复杂查询 + MyBatis-Plus 简单 CRUD，禁用字符串拼接 |

### 2.3 权限校验

```java
// 接口级权限校验
@PreAuthorize("@ps.hasPermission('clue:create')")
@PostMapping("/clue")
public Result<Void> create(@Valid @RequestBody ClueSaveDTO dto) { ... }
```

权限服务 `PermissionService.hasPermission(code)` 从 JWT 中获取当前用户权限列表并匹配。

## 四、前后端通用约定

### 4.1 字段映射

- 数据库 `snake_case` ↔ 接口/前端 `camelCase`
- MyBatis-Plus 配置 `map-underscore-to-camel-case: true` 自动映射

### 4.2 日期格式

- 接口传输：`yyyy-MM-dd`（日期）或 `yyyy-MM-dd HH:mm:ss`（时间）
- 前端展示：`dayjs` 格式化，与接口格式一致
