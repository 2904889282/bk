## 一、通用基础规则

### 1.1 命名映射规则

| 层级 | 命名风格 | 示例 |
|------|---------|------|
| 数据库表/字段 | `snake_case` | `clue_name`, `client_company` |
| 前端/接口 JSON | `camelCase` | `clueName`, `clientCompany` |
| Java 实体 | `camelCase` + `@TableField` | `clueName` → DB `clue_name` |

### 1.2 通用审计字段（所有业务表强制包含）

| 数据库字段 | 类型 | 填充方式 | 说明 |
|-----------|------|---------|------|
| `create_by` | bigint | 框架自动 | 创建人用户ID |
| `create_time` | datetime | 框架自动 | 创建时间 |
| `update_by` | bigint | 框架自动 | 最后更新人ID |
| `update_time` | datetime | 框架自动 | 最后更新时间 |
| `is_deleted` | tinyint(1) | 业务层可控 | 0=正常, 1=已删除（软删除） |

### 1.3 通用约定

- **主键**：所有表统一 `id bigint AUTO_INCREMENT`
- **字符集**：`utf8mb4`，排序规则 `utf8mb4_unicode_ci`
- **引擎**：`InnoDB`
- **时间字段**：`date` 类型存日期，`datetime` 类型存时间戳

## 三、线索状态流转规则（强制）

### 3.1 标准推进链路

```
线索接触 → 沟通提案 → 执行测试 → 已承接 / 已丢失 / 已延期
                                        ↓
                                    已转项目（终态锁定）
```

### 3.2 强制流转规则

| 规则 | 说明 |
|------|------|
| **正向推进** | 正常业务按顺序推进，**禁止跳步**（如从「线索接触」直接到「已承接」） |
| **管理员回退** | 管理员可手动回退状态，应对客户需求反复等特殊场景 |
| **已转项目终态** | 线索转为项目后，**自动锁定只读**，禁止再编辑基础信息、修改状态 |
| **已延期可重启** | 延期搁置的线索可随时重启，回到对应推进阶段；超 30 天未重启进入预警 |

### 3.3 状态变更强制关联

每个状态变更必须：① 填写跟进记录（核心结论 + 详细内容）② 自动生成操作日志 ③ 更新下次跟进截止时间

## 四、项目等级定级标准

| 等级 | 预算范围 | 说明 |
|------|---------|------|
| **A** | ≥100万 | 战略级高价值项目，或对公司有品牌/战略意义 |
| **B** | 10-100万 | 常规重点项目，标准交付流程 |
| **C** | ＜10万 | 小型/客情项目，轻量化交付 |
